# 文档审查与去 AI 味（doc-review）

## 流程（四步，别跳）

### 1. 定体裁

| 文稿 | genre |
| --- | --- |
| 简历、述职 | `resume` |
| 方案、汇报、工作总结 | `report` |
| 说明书、技术文档、操作手册 | `doc` |
| 公众号、知乎、专栏 | `article` |
| 营销文案、种草、推广页 | `marketing` |
| 标书、商务应答 | `bid` |
| 邮件、通知、公告 | `email` |

体裁决定维度的权重和词表，选错等于用错尺子。

### 2. 跑审计

```
deai_audit({ genre: "<上表>", detail: "full", text: <全文> })
```

长文档（>3000 字）分批跑，每批一个逻辑段落群，别一次塞整本。

### 3. 只改打标句

- 先改 `blocking`，再挑 `advisory` 里信息量最大的 5–8 条。
- 改法是换结构，不是换同义词：
  - 标签式开头（“负责：…”）→ 完整句，带动作和结果。
  - 空泛词（赋能/闭环/抓手）→ 具体做法 + 对象 + 数字。
  - 没有具体信息 → 补对象、数量、时间、地名、系统名。
  - 一句太长 → 拆两句，长短交错。
  - 三连并列 → 留最关键的 1–2 项。
- **不删事实**；专业术语（PMP、GIS、驻场、联调、标段）不算 AI 味。

### 4. 复检

再跑一次 `deai_audit`：总分进 15–25、无 blocking 就停手。然后**读出声**，念着别扭的地方再改一遍。

## 各体裁的硬要求

- **简历**：每条都要有“做了什么 + 对象/规模 + 结果”。别用“主导/赋能/闭环”，用“带 3 个人”“跑通 6 个派出所”。
- **方案/汇报**：写清做什么、谁来做、边界在哪、怎么验收；删掉“高度重视、持续完善、进一步加强”这类正确废话。
- **文档**：每段开头给结论，再给依据；删掉“如上所述、详见下文、需要注意的是”这种过渡腔。
- **公众号**：要有立场和一个具体例子；“首先/其次/综上”和每段三句是重灾区。
- **营销**：场景 + 细节 + 反差，别堆“极致、全新升级、不容错过”。
- **标书**：承诺要可验收，排比要少；写“7×24 响应，2 小时到场”，不写“优质高效、全力保障”。
- **邮件**：第一段说目的和要对方做什么；删掉“敬请知悉、特此通知”的套壳。

## 输出格式

```
文体：report　总分 46 → 改后 21
改了 7 处（blocking 2 / advisory 5）
1. 第 4 段「高度重视…进一步加强」→ 改成“把 3 条流程并成 1 条，平均 40 分钟出证”
2. ...
未改动：数字、人名、系统名、标段号
```

## 与旧 deai-audit 的差别

- 旧版六个体裁 + 固定打分；现在多了 `doc` 体裁，打标句带**行号**和**阻断级**，每个体裁有独立门禁。
- 门禁口径没变：文档总分 ≤25 且无 blocking 才交付。
- 小说别用这个 skill，用 `novel-write` / `novel-review`，那边看的是 blocking 数不是总分。
