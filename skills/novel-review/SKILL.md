# 小说审稿（novel-review）

两道工序，别混成一道：**机器管确定性硬伤，人管结构和读感。**

## 一、机器 lint（先跑，10 秒）

```
deai_audit({ genre: "fiction", detail: "full", text: <整章或片段> })
```

看三个数：

- `counts.blocking`：必须 0。>0 就按 `line` 逐条改。
- `counts.advisory`：3–5 条正常，>15 条再压。
- `score`：只当趋势。40 分但 blocking=0 的章，可能只是节奏慢，不一定是 AI 腔。

如果项目里有状态文件，再跑一次一致性检查：

```powershell
node scripts/story-state.mjs check --dir <项目>
```

## 二、三视角人读

每个视角只问一个问题，别写成万金油点评。

### 1. 读者视角：想不想看下一章

- 开头 300 字有没有一个具体的“不对劲”（异常、反常、未完成的动作）？
- 本章有没有至少一个读者能复述的场面（谁、在哪、做了什么）？
- 章末钩子落在哪：动作 / 未说完的话 / 新信息。落在“他不知道的是……”就是偷懒。

### 2. 编辑视角：这章在干什么

- 用一句话说清本章的变化。说不出来，说明这章是过场，要么合并要么加事件。
- 主角做了哪个**有代价的选择**？没有代价的选择等于没选择。
- 信息释放：读者这章新知道了什么？如果和上一章一样，就是原地踏步。
- 爽点/情绪点是否落地：写在场的人的具体反应，不写“全场震惊”。

### 3. 一致性视角：有没有吃书

- 人名、称呼、年龄、关系、地点、时间线，和 `追踪/上下文.md` 对不对得上。
- 人物知道的事，是不是他“该知道”的（作者真相 vs 读者已知）。
- 前章埋的伏笔，这章有没有被写反或提前揭示。

## 三、给分（5 维 ×10 分，见 references/review-rubric.md）

| 维度 | 看什么 |
| --- | --- |
| 开篇拉力 | 前 300 字有没有异常和期待 |
| 场面具体度 | 能不能拍成镜头 |
| 人物行为 | 选择有没有代价、动机是否自洽 |
| 节奏 | 一段一件事，长短句交替，无注水 |
| 语言干净度 | blocking=0，比喻不落套，不替读者总结 |

总分只用于**同一本书内纵向比较**，不要跨书比，也不要拿它当发布门槛。

## 四、输出格式

```
本章结论：可发 / 改后发 / 重写
机器：blocking 0，advisory 6，score 28
读者视角：1 条（最影响追读的那个问题）
编辑视角：1 条（本章变化 + 有没有代价）
一致性：1–3 条具体位置
必改（按优先级）：
  1. 第 37 行：情绪判词，改成动作
  2. ...
可改可不改：...
```

**不要**输出“语言流畅、情节紧凑、人物鲜明”这种谁都能贴的评语。

## 五、边界

- 只审用户给的这一章/这一段，不擅自改全文。
- 改法给到具体句子，不给“建议更具体”这类空话。
- 类型套路（退婚、系统提示音、扮猪吃虎）不算 AI 痕迹，看执行细节。
